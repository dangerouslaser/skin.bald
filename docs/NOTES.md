## Home rows built per install (2026-09-26)

- **Generated include is per install.** Skin Variables writes `1080i/script-skinvariables-generator-includes.xml` into the skin folder, which is this repo through the Kodi symlink, so the committed copy had become one developer's rows ("Random movies" first) rather than the defaults. It is now gitignored and untracked. `1080i/Includes_Bald_HomeDefaults.xml` (tracked, shipped) is what the generator builds from the shipped `shortcuts/skinvariables-shortcut-*widgets.json`; `python3 tools/build_home_defaults.py` rebuilds it, and a unit test fails when it is stale. Pattern from Arctic Fuse 3's `Includes_Fallbacks.xml` (ideas only, no code).
- **Why the fallback works.** `Includes.xml` loads the generated file early and the fallback last. Kodi keeps the first definition of an include, variable or expression name (`CGUIIncludes::LoadIncludes`, `LoadVariables` and `LoadExpressions` all use `try_emplace`, checked in xbmc master), and a missing include file is only logged at INFO (`Load_Internal`). So a fresh install or a clean clone uses the defaults, and a built install uses its own rows. Every name the generator writes is written whatever the row count (an empty `<definition>`, `[false]` expressions), so a build never mixes with the fallback's rows.
- **Only configured rows are bound.** `tools/build_home_row_bindings.py` and its 200 KB `Includes_Bald_HomeRows.xml` bound all 60 possible row ids (about 120 caption groups and 360 clearlogo images on Home). The generator now writes, per screen, only its configured rows: `Bald_ConfiguredArtLogos_<screen>` / `Bald_ConfiguredCaptions_<screen>` (combined by `Bald_ConfiguredArtLogos` / `Bald_ConfiguredCaptions`), `Bald_ItemOdd_<screen>`, `Bald_HasLogo_<screen>` and the two `Preview` forms (ORed by the old expression names in `Includes_Bald_Home.xml`), and the flat `Bald_Fanart` / `Bald_Logo` variables. The variables keep their exact old order: preview values for every row, then `$EXP[Bald_WidgetPreview]` giving empty (the old unconfigured preview branches returned an empty thumb, so a preview of a screen with no matching row stays blank), then the current-row values. They stay one flat variable, not per-screen variables nested with `$VAR`, because the dialog art depends on variables being evaluated with Home's window context and nesting was not checked live.
- **One "art row" property was considered and not done.** A single property for the row whose art shows would halve the variable branches, but it would have to be kept in step from every place that changes `Bald.Row`, `Bald.Row.<screen>`, `Bald.Menu` or `Bald.MenuPreview`, including the idle timer (500 ms granularity) and the dialog guards. With 3 to 8 rows the preview/current pairs now cost a handful of branches, so the expression pairs stay.
- **Generator syntax.** Checked against the installed Skin Variables 2.2.4 (`resources/lib/shortcuts/template.py`, `xmltojson.py`, jurialmunkey `parser.parse_math`): `$MATH[]` takes space-separated tokens evaluated left to right with no precedence; rule conditions `a==b` / `a!=b` are compared in Python, anything else goes to `xbmc.getCondVisibility`. Bald's generator uses only the Python comparisons, so `tools/build_home_defaults.py` can reproduce the build. Its output was compared byte for byte with the real `ShortcutsTemplate.create_xml` (Kodi modules stubbed) for the shipped defaults, and the real code also built cleanly from the live row lists in `userdata/addon_data/script.skinvariables/nodes/skin.bald/`.
- **Multi-line expressions.** Parts are joined with newlines. Kodi's `InfoExpression::Parse` skips whitespace only after an operator (Kodi turns off TinyXML whitespace condensing), so every generated expression line starts with `| [` and ends with `]`; a test checks this.
- **When it builds.** Home's `onload` runs `RunScript(script.skinvariables,action=buildtemplate,lastbuildtime=$INFO[Skin.String(Bald.WidgetsStamp)])`. Skin Variables' `update_xml` hashes its arguments, the generator config text and the current output file, compares with `Skin.String(script-skinvariables-generator-hash)` and returns when they match; otherwise it writes the file, stores the new hash and calls `ReloadSkin()`. So it builds on first run (no file, no hash), when the widget editor has closed since the last build (Custom_1116's `onunload` stamps `Bald.WidgetsStamp`), and after a skin update that changed the generator: `tools/build_home_defaults.py` writes a digest of `shortcuts/generator/` and the row defaults into the config's `buildv`, because the hash covers only the config text. The editor used to rebuild with `force` as it closed; the rebuild (and its skin reload) now happens on the next Home load, as in Arctic Fuse 3. The first Home load after this change rebuilds once, since the arguments changed.
- **Row start for every row.** The one-shot `bald_rowstart_*` timers covered only 9101 to 9103, 9201 and 9301; rows 9104+, 9202+ and 9302+ kept the fixedlist's pristine item 3. Timers.xml cannot be generated, so the timers stay for the rows that can show before they are focused, and two actions cover the rest: each generated row's `onfocus` moves the next row back while that row is hidden and already loaded (rows count as visible until their items load, docs "Hidden lists do not load"), and `Bald_Row`'s own `onfocus` corrects a row that is still pristine when focused (it slides while fading in; only happens when the viewer outruns loading). All paths share the `Bald.Start<id>` mark, which Home's `onload` clears for every configured row (`Bald_RowStartReset`). Kodi evaluates all of an action list's conditions before running any action and runs skin actions and skin timers on the GUI thread, so two paths cannot both move a row. A row is marked once focused with items, so later item 3 at slot 2 is left alone. Pre-existing caveat, now for every row: Home's `onload` clears the marks on every load, so a row the viewer left on item 3 at slot 2 before leaving Home (for example to play something) is moved back to item 1 when it is next focused, as the timers already did for the first three rows.
- **Row dots and the menu note.** Each generated row passes `dots` (the name of a generated `Bald_RowDots_<id>` include: one dot per row of its screen, the current one bright) and `dots_width` to `Bald_Row`, which includes `$PARAM[dots]` (a parameter as the include name, as Arctic Fuse 3 does). The head variable is written for every screen and is empty without rows.
- **No rows.** The widget editor hides Remove widget on a screen's last row, but a row list can still be emptied by hand. The generator writes `Bald_HasRows_<screen>` (`[false]`, plus `| [true]` per row). With no Home rows, Home's `onload` clears `Bald.Row` and focuses the menu's Home entry (which opens the menu) instead of leaving `defaultcontrol` 9101 pointing at nothing; menu Back only closes the menu while there is a current row; the idle wake button focuses `$VAR[Bald_RowFocus]` (the current row, else 9001), and ambient advance skips an empty `Bald.Row`. Entering a screen from the menu requires that screen to have rows.
- **Home menu navigation belongs to the grouplist.** Commit 390441c gave each menu button hand-written Up/Down chains for every combination of hidden Movies, TV shows and Live TV, setting `Bald.MenuPreview` and `TMDbHelper.WidgetContainer` before moving, because the menu was then a plain group. Since 6e08b0e made it a grouplist, those chains have not run: `CGUIControlGroupList::AddControl` replaces each child's Up and Down actions with its neighbours (`SetAction(..., replace=true)`; only Left, Right and Back are kept when set), and `CGUIWindow::OnMove` follows a hidden neighbour's own navigation to the next focusable one. So the preview has come from each button's `onfocus` alone, which runs as focus lands. The chains and their ~40 parameters are gone: `Bald_HomeMenuButton` takes id, label, preview, visible, suffix and right, and what Select does is passed as nested `<onclick>` children (`Bald_HomeMenuScreen` for Home, Movies and TV shows, which also retargets TMDb Helper in `onfocus`). - **Left runs Select.** Left used to repeat each entry's four actions; it is now `Action(Select)`, which Kodi sends to the focused control (the button, since a Left with no navigation keeps focus) and which runs the same `<onclick>` list. Not checked live.

## Milestone 3

- **Animation model (final).** Kodi animations are state-driven: Visible/Hidden fire on edges of a visibility condition and Conditional animations expect their condition to hold. Every item-change transition is therefore keyed to a state that flips on each move and then holds: the parity of the current row's item position (`Integer.IsOdd(Container(c).CurrentItem)`). Each animated piece exists twice (Odd and Even): the incoming instance becomes visible and plays its Visible animation; the outgoing one hides. Images keep their old texture while a Hidden animation plays (`CGUIImage::UpdateInfo`), so fanart and clearlogos fade out showing the old picture, a true crossfade; hidden images keep updating otherwise, so they are never stale when shown again. Labels cannot freeze, so caption text has no Hidden animation and disappears at once while the new text staggers in. Row swaps and the menu use Visible/Hidden on groups keyed to `Bald.Row` and `Bald.Menu`. Known gap: the ambient advance wrapping from the last to the first item of an odd-length row keeps the parity, so that one step swaps without animating.
- **What did not work, and why.** (1) `Container.OnNext` / `OnPrevious` as the condition of `reversible="false"` Conditional animations: true for one frame only, and `CAnimation::UpdateCondition` resets a non-reversible animation when its condition turns false, so animations started and were cancelled. (2) Skin timers recording the shown item: `CSkinInfo::ProcessTimers` runs from `CApplication::ProcessSlow`, every 500 ms, so updates lagged at random (judder). (3) Hiding on `OnNext` in `<visible>`: worked for text but led to layered fanart workarounds that ghosted. (4) `Container.Scrolling` in a hide condition: briefly true at the end of every scroll, which blinked the caption out after each scrolling move.
- **Comparing two infolabels.** `String.IsEqual(A,B)` compares two infolabels directly. `$INFO[...]` inside a condition fails to parse in `Timers.xml` ("Misplaced ["); it is fine inside actions. Do not quote `SetProperty` values (quotes are stored literally).
- **Skin timers are slow.** They run every 500 ms: fine for the row-start fix, idle and ambient, never for per-item behavior. A timer's stop condition must not depend on the thing it tracks, or it can get stuck running.
- **Fanart.** Two parity layers (`Bald_ArtLayer`): the incoming layer fades in (700, sine) while zooming 1.05 to 1.0 (1500); the outgoing layer fades out (700) with the old art. A row swap that keeps the parity changes the visible layer's texture, which `<fadetime>700</fadetime>` crossfades (Kodi 22 waits until the new image has loaded, then fades the old one out behind it).
- **Clearlogo preload.** Logos not yet in Kodi's texture cache could arrive after their fade-in ended and pop. A `<fadetime>` on the logo fixed that but crossfaded from the previous logo, so old logos ghosted under new ones. Instead each row tile draws an invisible (alpha 0) copy of its item's clearlogo, which loads it into the texture cache while the tile is on screen.
- **Do not use `Container.Scrolling` for hide conditions.** It is true while the scroll timer has run longer than the scroll duration, which includes a frame at the end of *every* 440 ms row scroll before the timer stops. Used in the caption's visibility it hid the caption for that frame, so every scrolling move faded the caption in, blinked it out about 450 ms later, and faded it in again (measured from a screen recording). Hold-while-fast-scrolling comes for free instead: each repeat of a held key hides the caption (`OnNext`) and restarts its delayed fade-in, so it stays hidden until the key is released.
- **Measuring motion.** Kodi's screenshot action is too slow and counts as input. Record the Kodi window with `screencapture -v -V 3 -x -R<x,y,w,h>` (Kodi must be frontmost and awake), extract frames with `ffmpeg -fps_mode passthrough`, and track mean brightness of screen regions per frame to find pops.
- **Art and caption follow the current row, not focus.** With the menu (or the idle wake button) focused, `ListItem.*` no longer points at a row, so the art frame and captions read `Container(9101..9103)` selected by the `Bald.Row` window property. Captions and clearlogos are one instance per row (includes with a container param).
- **Zoom clipping.** Neither a group nor a grouplist clips a zoom-animated texture, so the 1.05 settle zoom spilled outside the frame. Four field-colored mask bars around the frame hide the overflow. Revisit for milestone 4, where the frame zooms to full screen and the masks must get out of the way.
- **Hidden lists do not load.** Kodi skips `Process()` for hidden controls, so a hidden row's content was only fetched when first shown (and its start-item fix ran visibly late). Rows now count as visible until their items have loaded.
- **Window properties survive ReloadSkin.** Home's `onload` resets `Bald.Row`, `Bald.Menu` and the row-start flags every time.
- **Focus while hidden.** The menu list and rows use `<visible allowhiddenfocus="true">` so `SetFocus` works before the fade-in has made them visible.
- **Edge nudge.** Replayed by flipping a window property between `a` and `b` in one atomic `SetProperty` (via a variable), so each press retriggers a `reversible="false"` animation.
- **Menu hint counter.** `Skin.String(Bald.MenuOpens)` counts opens. The spec hides the "Back for menu" hint at 3; that is disabled for now (it kept looking like a bug during development) and returns in 0.2 as an Appearance setting. Reset it with JSON-RPC `Settings.SetSkinSettingValue` (`setting: "bald.menuopens"`, `value: ""`), since skin setting ids are lower-cased there.
- **Idle.** `bald_idle` (60 s) closes the menu and parks focus on an invisible button (9199) so the first key press only wakes. `bald_ambient` advances the current row every 8 s while idle (turn off with `Skin.SetBool(Bald.AmbientOff)`; the Appearance setting comes in 0.2). The drift is two `pulse` slides, 2 px on x (23 s) and y (31 s). Note: Kodi's screenshot action counts as input and ends idle.
- **Keyboard Back.** On a keyboard, Esc sends `PreviousMenu`, not `Back`, so it does nothing on Home. Backspace (and a remote's Back) opens and closes the menu.
- **Movies, TV shows, Live TV, Search** are menu placeholders with no rows yet; highlighting one previews a note in the row area, and Select or Left keeps you in the menu.
- **Caption title wraps upward.** The title is a `textbox` with `<height max="132">auto</height>` (up to 3 lines of 44 px) inside its own vertical grouplist with `<align>right</align>`, which bottom-aligns it (`CGUIControlGroupList::GetAlignOffset`). ## Background (pulled forward from section 7)

- **Tinted field, tried and replaced.** TMDb Helper's colors feature (mean color of a 128 px thumbnail, lightness and saturation forced by `Skin.String(TMDbHelper.Colors.Luminance)` / `...Saturation`) gave a field color, but at the spec's 7% lightness even 35 to 60% saturation reads as near-black (7% lightness caps the brightest channel at about 14%). Its own color stepping floors each step to an integer, so dark colors jumped; a two-layer crossfade fixed that. The user preferred a blurred fanart background instead, so the color tint was removed (see git history for the layers and timer).
- **Blurred fanart.** TMDb Helper's blur (`plugin.video.themoviedb.helper` 6.17.4, `lib/monitor/images.py`): the skin sets `Skin.SetBool(TMDbHelper.EnableBlur)` and `Window(Home).Property(TMDbHelper.Blur.SourceImage)` = `Art(fanart)|Art(tvshow.fanart)|Art(thumb)`, leaves `TMDbHelper.Service` off (no TMDB lookups), and names the watched row in `TMDbHelper.WidgetContainer` (set by each row on focus). It publishes `Window(Home).Property(TMDbHelper.ListItem.BlurImage)`: a 480 px copy with a Gaussian blur of radius 40 (`Skin.String(TMDbHelper.Blur.Size)` / `...Radius` change these), cached as JPEG under its addon_data. The background image darkens it with `colordiffuse` `bald_backdrop` (30%) and crossfades with `<fadetime>800</fadetime>`, which waits for the new image to load.
- **Menu preview backdrop.** Kodi's static list items do not provide a per-item focus action, so the main menu uses a grouplist of focusable buttons. Each button sets `Bald.MenuPreview`; Home, Movies and TV Shows also retarget TMDb Helper to that screen's remembered widget row. The foreground preview, clearlogo and cached Gaussian backdrop therefore share one explicit screen selection and remain synchronized without substituting sharp fanart while the menu is open.
- **Frame masks as windows.** The bars that hide the art frame's settle-zoom overflow are grouplists (which clip ordinary textures) containing the same full-screen background offset back to 0,0, so they line up with it exactly (`Bald_BackdropWindow`).
- **Accent and ink** stay neutral.
- **Letterboxing.** The skin defines only a 16:9 layout; fullscreen on a non-16:9 display (the MacBook's built-in screen is about 1.55:1) shows a black band.

## Test hardening (2026-09-26)

- Tests no longer compare condition text. `tests/conditions.py` parses a Kodi condition (`!` binds tightest, then `+`, then `|`; `[...]` groups; `$EXP[...]` flattened) into a small decision diagram, so tests ask `equivalent(a, b)` ("means the same"), `implies(a, b)` ("only shows when b") and `same_actions(...)` for (condition, action) lists. Moving a condition into an `<expression>`, reordering its terms or adding brackets no longer fails a test; changing what it means still does. `tests/test_conditions.py` covers the helper and checks every condition in `1080i` parses. The older `kodi_includes.condition()` text normalizer was removed.
- Tests that asserted include plumbing (`<width>$PARAM[width]</width>` plus a param default) now expand the call with `kodi_includes.expand_call()` and check the output (the clearlogo box, info action Down routes, hint pair, captions, poster item, menu dot, row dots, dialog buttons, guide grid id).
