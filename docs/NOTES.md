# Build notes

Things from docs/SPEC.md that did not map directly onto Kodi 22, with what was tried and what was done instead.

## Kodi's settings windows in the Bald scaffold (2026-09-26, not yet run in Kodi)

Static checks only (`tools/kodi_dev.py validate`, the unit tests); nothing here has been reloaded or driven in Kodi.

- **What changed.** `Settings.xml` (the hub), `SettingsCategory.xml` (every core settings page), `SettingsProfile.xml` and `SettingsSystemInfo.xml` now draw the same scaffold as Bald Settings (`Includes_Bald_Configure.xml`): the field and backdrop, the 590 px sidebar with the title at 96,96, a category column in the Home menu's language (Bald_MenuItem at 34%, accent dot on focus), a detail pane at x 686, and sentence-case hints on the y 954 line. `SettingsScreenCalibration.xml` is unchanged. The four windows are now Bald-native in the tests (`tests/kodi_includes.py` NATIVE, `tests/test_localization.py`), so they follow the constants, ID map, string and reference rules; `tests/test_native_settings.py` checks their Kodi contract and look. New shared includes: `Bald_SettingsOpen` (the Open button, also used by Bald Settings), `Bald_SettingsRowStyle` (the row look without radio dots; `Bald_ConfigureButton` is now it plus the dots, same output), `Bald_SettingsCategoryButton`, `Bald_SettingsCategoryGroup`, `Bald_SettingsTemplate`, `Bald_SettingsSpinner`, `Bald_SettingsSlider`, `Bald_SettingsColorButton`, `Bald_SettingsGroupTitle`, `Bald_SettingsSeparator`, `Bald_SettingsScrollbar`, `Bald_SettingsHelp`, `Bald_SettingsProfileItem`, `Bald_SystemInfoLine` and `Bald_SystemInfoMeter`; `Bald_SettingsFrame` and `Bald_SettingsDetail` gained `title_id` / `heading_id` so Kodi can fill the heading label by id. New textures from `tools/textures.py` (`settings_textures()`): `bald/chevron.png`, `bald/slider_bar.png`, `bald/slider_nib.png`. Strings 31950-31966 were added; no colours or fonts.
- **Control ids, checked against xbmc master (Kodi 22).** `CGUIDialogSettingsBase` binds 2 heading, 3 category grouplist, 5 settings grouplist, 6 help text, and the templates 7 button, 8 radio button, 9 spinner (spincontrolex), 10 category button, 11 separator image, 12 edit, 13 slider (sliderex), 14 group title label, 15 colour button; `CGUIWindowSettingsCategory` adds 20 (settings level, label set to 10036 + level). - **Rows are templates.** Kodi clones 7-15 for every setting and sets each clone's width to grouplist 5 (1106 px, x 686 to 1792, with a 4 px scrollbar at the right safe edge). All row templates share the scaffold row: Bald_Section at 45%, full ink with the accent dot and a 6 px slide on focus, 28% when disabled, values right-aligned 26 px in. Toggles show the scaffold's state dot (accent on, dim off); spinners draw chevrons either side of the value (the left one is the texture flipped); the slider is a 240 px, 4 px track with a 16 px nib (the track texture is 16 px tall because Kodi scales the nib by the control height over the track texture's height); the colour button's swatch is a 20 px dot placed 26 px in (Kodi would put it flush right, where the focus slide clips it); group titles are Bald_RowLabel at 60% pushed down with `textoffsety` (Kodi reads `aligny` bottom as top); separators are a 10% hairline. "Reset above settings to default" is Kodi's clone of template 7 at the end of each category.
- **Category focus.** While focus is in the settings, `CGUIDialogSettingsBase::DoProcess` keeps the current category button focused at half alpha, which gives the scaffold's dimmed dot without a list. The category buttons therefore only fade on focus and do not slide: Kodi re-focuses the button whenever focus leaves it, and a slide would jump.
- **Deliberate differences from the Bald Settings windows.** The settings pages have no detail heading, because Kodi exposes no infolabel for the current category once focus leaves it; the sidebar keeps it marked instead, and the help text (6) sits under the rows at y 846 rather than under a heading. The hub is one scrolling list of fifteen entries (eleven show at once) with a note and Open for each; the core page notes are Bald strings because Kodi's own section help strings are uneven (Games' is a joke). Profiles are scaffold rows with a round avatar, the last login, and an accent check on the profile in use (Kodi marks it selected). No window has an `onback`; Kodi's Back saves the settings and retraces history (`tests/test_bald_settings.py` covers the four files).
- **Not done.** The settings dialogs (`DialogSettings.xml`, `DialogAddonSettings.xml`) still use Estuary's look; they use the same template ids and could share these includes next. The Estuary spin arrows and slider textures in `Defaults.xml` still apply to every other window.

## Home row styles (2026-09-26, not yet run in Kodi)

- **Where the style lives.** Each row in the Skin Variables row lists (`addon_data/script.skinvariables/nodes/skin.bald/*widgets.json`) can carry a `style` field next to `label`, `path` and `limit`: `fanart`, `thumbnail`, `logo` or `poster`. The shipped defaults (`shortcuts/skinvariables-shortcut-*widgets.json`) have no field, and the generator maps an empty or unknown value to `fanart` (a `<rules>` block in `shortcuts/generator/screen.xml`, compared by Skin Variables itself, so `tools/build_home_defaults.py` reproduces it). The generated row passes `style` to `Bald_Row`, which includes `Bald_RowTiles_$PARAM[style]` inside its fixedlist for the list's position, size and item layouts, the same parameter-as-include-name pattern as the row dots.
- **Styles.** Fanart is the old tile, unchanged. Thumbnail is the same 176 x 99 tile with `Bald_ItemThumbnail`: an episode's still (`Bald_EpisodeThumb`: thumb, fanart, show fanart), otherwise `Art(landscape)`, otherwise the fanart chain; a movie's `Art(thumb)` is not read, since it is usually the poster. Fanart with logo is the fanart tile with `Bald_TileLogo` over it: `Bald_ItemLogo` (clearlogo, else the show's) at most 100 x 34, 8 px in from the tile's bottom left, over `scrim_logo.png` clipped to the tile's corners; the overlay hides without a logo and with Appearance's clearlogo setting off, and dims with the unfocused tile.
- **Editor.** The widget editor (1116) has a Style row after Items per row, its `label2` showing the current style (`Bald_WidgetStyleLabel`). It runs Skin Variables' `do_edit` with its choice-list form, checked against the installed 2.2.4 (`resources/lib/shortcuts/node.py` `do_edit(key, value, heading, use_prop_pairs)`, `plugin.py` splitting the path on `&&` and `unquote_plus`-ing each part): `&func=do_edit&&style&&Fanart=fanart&Thumbnail=thumbnail&...&&Style&&True`. The labels are `$LOCALIZE` strings and must not contain `&`, `=`, `,` or `+` (a `+` would become a space), hence "Fanart with logo". Picking a style writes the row list; closing the editor stamps `Bald.WidgetsStamp` and Home rebuilds on its next load, as for any other row edit. The generator's `buildv` digest changed, so an installed build rebuilds once.
- **Poster rows.** `Bald_RowTiles_poster` is view 515's rail: `Bald_PosterLowTile` (140 x 210 in 156 px slots, `Bald_LibraryPoster`, so episodes fall back to the season's, then the show's poster) at 96, 738 (`Bald_LowRailTop`, a new constant now also used by views 515 and 523), 1248 x 234, with the landscape tile's invisible clearlogo preload (now `Bald_TileLogoPreload`, shared). The row label line moves to y 712 (`Bald_RowLabelTop_<style>`), 12 px above the posters as on landscape rows.
- **Focus slot and row start.** The generator writes `slot` (5 for poster rows, else 2) and `start` (slot + 1, the item a fresh fixedlist selects) per row; `Bald_Row` uses them for `focusposition`/`movement` and for its own start correction (`Control.Move(id,-slot)`). The correction the row above runs for a hidden next row is now a generated `Bald_RowStart_<id>` include written with that row's own slot, and each row includes its successor's, because a row's generator loop cannot read the next row's style. The five `bald_rowstart_*` timers (Timers.xml cannot be generated) accept either pristine state, item 3 at position 2 or item 6 at position 5, and move by 2 or 5 with conditional `onstart`s; a landscape row's cursor never reaches position 5, so the two cannot be confused. Pre-existing caveat, now for poster rows too: a row with fewer items than its start item is never pristine in this sense and opens wherever Kodi puts it.
- **The frame shrinks.** `Window(home).Property(Bald.RowStyle)` holds the displayed row's style and `Bald_PosterRow` tests it; a property rather than a `Container(...)` condition because `<visible>` and animation conditions lose Home's window context under modal dialogs ("Conditions have no window context"), so dialogs over a poster row keep the small frame. It is set by the row's `onfocus` (and its `onup`/`onback` into the menu), Home's `onload` (`$VAR[Bald_RowStyle_home]`), each menu entry's `onfocus` (`Bald_PreviewRowStyle`: the previewed screen's remembered row `Bald.Row.<screen>`, through the generated `Bald_RowStyle_<screen>`; empty for Live TV, Search and Settings), entering a screen from the menu, and the idle wake button (the idle timer closes the menu, so the current screen's row shows again; `Bald_ScreenRowStyle`). Kodi cannot animate size, so Home's masks (`Bald_HomeFrameMasks`, separate from `Bald_ArtFrameMasks`, which the info dialog's recommendations page keeps unchanged) reach the top of the screen and the bottom mask is 156 px tall; on a poster row it slides up 126 px, the art frame group slides up 63 px so the crop stays centred, and the logo scrim and clearlogo group slides up 126 px (paired non-reversible Conditionals, 540 MOVE after 30, docs/SPEC.md 5.1).
- **Sliding a clipped mask misaligns it.** `CGraphicContext::SetClipRegion` and `ClipRect` work in origin coordinates and ignore animation transforms (checked in xbmc master), so a grouplist clips first and then the whole clipped result is moved by its animation: the slid bottom mask shows the background 126 px off, and a counter-slide inside it would cancel the slide rather than realign the content. A second, fixed mask over 696-852 therefore fades in (200 after 370) once the slide has settled and out (150) as a landscape row comes back, so a poster row rests on an aligned mask and the offset only shows while the edge moves. On the very first load onto a poster row that mask plays its fade-in once. Without TMDb Helper's blur the masks are plain field and the offset is invisible.
- **Info handoff.** The image behind the mask is still 1248 x 702. While info is open the art's 63 px nudge is undone in step with the zoom (640 MOVE after 40, a third Conditional on `Bald_PosterRow + Bald_InfoOpen`), so the zoom to 153.846 about 274,343 lands exactly as from a landscape row, not 63 px high; the masks have faded out (60 ms) by then, which reveals the art's hidden 63 px above and below the small frame as the zoom starts. Closing info moves the art up again with the zoom back (540 after 30), and the masks, which kept their poster position, fade back at 620. The clearlogo and scrim keep their poster offset during info; they are faded out for it.
- **To verify in Kodi (static checks only so far):**
  - moving Up and Down between fanart and poster rows in both directions: the frame edge, art, clearlogo and scrim move together with the row swap, the label line and rail land cleanly, and a poster row rests on an aligned mask with no visible seam in the blurred background;
  - the menu preview of a screen whose remembered row is a poster row (the frame shrinks while previewing it and grows back when moving to a screen on a landscape row, and to Live TV, Search and Settings), then Back and Left/Select from that preview;
  - info open and close from a poster row: the zoomed art fills the screen with no 63 px offset, related-title switches, and Back returning to the focused poster with the small frame restored;
  - dialogs over Home on a poster row (context menu, a confirm dialog, info): the frame stays small and the dialog art and logo sit in it;
  - row start on poster rows (the first Home row as a poster row via the timer, a later poster row via the row above, a poster row focused before it loads, and a poster row with fewer than six items);
  - each landscape style with movies, shows and episodes: Thumbnail shows episode stills and landscape art (and fanart where a movie has no landscape), Fanart with logo shows the logo only where one exists and hides it with Appearance's clearlogo setting off;
  - changing a row's style in the editor: the Style value updates at once, and closing the editor and returning Home rebuilds once (one reload) with the new style; also the first Home load after installing this, which rebuilds once for the new `buildv`.

## Milestone 5: TV info (2026-09-26, not yet run in Kodi)

Built and statically validated only (XML parse, include resolution, unit tests); nothing below has been reloaded or driven in Kodi. Treat every behavior as unverified until the checklist at the end passes.

- **Page model.** Shows, seasons and episodes get their own Overview (`Includes_Bald_InfoTV.xml`), page 0 of the existing paged dialog. Cast & details and More like this stay shared, so TV keeps its cast, details and show recommendations; Down from the episode row goes to Cast, and Up from Cast returns to the episode row (then the tabs, then the actions). The spec's TV screen lists no pages, and the prototype's TV screen has none; keeping the two shared pages avoids dropping features TV info already had.
- **Structural branch.** `DialogVideoInfo.xml` picks `Bald_InfoOverview` or `Bald_InfoTVOverview` (and the matching onload, dim and hints) with include conditions on `ListItem.DBType` (`$EXP[Bald_InfoTVItem]`), Arctic Fuse 3's pattern. This relies on Kodi reloading the window when an include condition changes value between opens. Only one overview is loaded at a time, so both keep the action grouplist id 5000 and the Cast page's Up route works for both. Conditions that must hold under a context menu read the `Bald.InfoTV` window property rather than `ListItem.*`.
- **Episodes now open the TV screen.** The 2026-09-25 episode Overview (episode title, parent-series S/E meta) is superseded for episodes; those branches in `Bald_InfoOverview` are now only reached if the include condition misfires. The TV header shows the show (logo with `tvshow.clearlogo` fallback, show title fallback), and the Cast page still shows the episode's own title and meta.
- **Layout (prototype TV screen, one column at x96).** Logo box y150 to 320; meta y346 (24/500); genres y384 (accent); two-line plot y424 (22 px, 34 px lines, 68 tall); actions y522; season tabs y620; episode cards y682 (list y670, 204 tall, 12 px pad for the pop); detail y894; synopsis y934 (one line, ellipsis). Content ends at y964, so the TV Overview has no page trail; with the episode row focused the right-hand hints read "Select to play · Down for cast & details". Stagger: 380 base plus 0, 60, 100, 180, 220, 270, 310.
- **Header.** For shows, labels are native (`ListItem.Year`, `Property(TotalSeasons)`, `ListItem.MPAA`, genre, plot) and appear at once. `scripts/info.py tvinfo` then publishes `Bald.TV.Meta` ("2019 to 2024, 3 seasons, TV-14"; the end year is the latest episode air date, since Kodi has no end year), which replaces the native line. Seasons and episodes have no show-level labels, so their meta, genre and plot come only from the script.
- **Actions.** An opened episode plays itself natively: "Resume S3 E2" `SendClick(9)` or "Play S3 E2" `SendClick(8)`. A show or season shows the script's next episode ("Resume S3 E2" or "Play S3 E2", "Play" until published) and plays it with `RunScript(skin.bald,play,episode,<id>)`, because Kodi's own Play on a TV show opens the library instead of playing. The script closes info first (as Kodi's Play does) and calls JSON-RPC `Player.Open` with `resume: true`. Next episode: the most recently played episode resumes if in progress; otherwise the first unwatched episode after it, then the first unwatched, then S1 E1 (finished shows start again). Specials only count if a show has nothing else. Trailer stays `SendClick(11)`.
- **Season tabs.** A native list (5301) on `videodb://tvshows/titles/<id>/` (the show's DBID, `ListItem.TVShowDBID` for seasons and episodes, or the script's `Bald.TV.ShowID`; an empty id gives no path rather than `titles//`). Kodi list slots have one width, so each tab is a 135 px slot (the widest single-digit label, 101 px, plus the prototype's 34 px gap) and labels are built here in English ("Season N", "Specials", "All seasons") so the underline can use widths measured from Instrument Sans Medium 24 (96, 101, 110, 114, 93, 124 px). Kodi's optional "All seasons" item shows as a tab. The underline grows from the left over 300 MOVE (a Focus zoom of `1,100` to `100,100`). Differences from the prototype: the selected tab keeps weight 500 (there is no 24 px SemiBold in `Font.xml`) and unselected tabs use 45% ink rather than 42% (nearest token).
- **Episode row.** A fixedlist (5302), `focusposition` 2 and `movement` 2 like Home's rows, 344 px slots (320 card plus 24 gap), 440 MOVE scroll, content `$INFO[Container(5301).ListItem.FolderPath]` (the native chaining Arctic Fuse 3 uses). Cards reuse `Bald_LandscapeTile` (now parameterized; Home's defaults unchanged) with the episode thumb, plus a bottom scrim (`scrim_card.png`, 72% to 0 at 55%), episode number and title (18/600, 1 px larger than the prototype's 17), a watched check (`check.png` on a 60% field dot) and a progress bar. Cards sit at 78% while the row is unfocused; with focus the others drop to 60% and the focused card pops to 1.05 with the ring. Select plays the episode (resuming) through the same script.
- **Season change.** The row's group fades out 140 and drops 14 px while `Container(5302).IsUpdating`, then fades in 340 and rises over 420 MOVE. These are paired non-reversible Conditionals, not `<visible>`, because Kodi does not process hidden lists (Milestone 3), so a hidden row would never finish loading. On a quick local load the "out" may be cut short. Kodi keeps a container's index when its content changes, so after changing season the row shows the same index until Down; Down then starts it at the first episode (`SetFocus(5302,0,absolute)`) unless the season is the one the row was last positioned for (`Bald.TV.RowFor`, compared with `String.IsEqual` on two infolabels). This relies on Kodi evaluating all of an action list's conditions before running any of them.
- **Opening position.** A fresh fixedlist starts on item 3 (Milestone 2). `tvinfo` waits (bounded, 5 s, 20 ms polls, identity-guarded, reading only the lists' own items) for the tabs to load, selects the opening season with `Control.Move`, waits for the row to hold only that season, then selects the opening episode: the opened episode, or the first episode of the next episode's season for a show (prototype). From an episode, focus then moves to its card, but only if it is still on the initial action. The row may visibly scroll if this finishes after the content has faded in (slow hardware). No timer was added.
- **Dim.** The prototype's `infoDim` is a 60% field layer at 70% opacity on the TV screen at rest (about 42% field in total). It is implemented literally (`bald_field60` at a static 70% fade) and sits under the Cast and More like this backdrop. The spec's "dims to 70% field" could also be read as a 70% field layer; confirm the intended strength when this is seen in Kodi.
- **Arctic Fuse 3** was used only as a reference for the include-condition branching and season to episode content chaining; no code or text was copied.

## Home rows built per install (2026-09-26)

- **Generated include is per install.** Skin Variables writes `1080i/script-skinvariables-generator-includes.xml` into the skin folder, which is this repo through the Kodi symlink, so the committed copy had become one developer's rows ("Random movies" first) rather than the defaults. It is now gitignored and untracked. `1080i/Includes_Bald_HomeDefaults.xml` (tracked, shipped) is what the generator builds from the shipped `shortcuts/skinvariables-shortcut-*widgets.json`; `python3 tools/build_home_defaults.py` rebuilds it, and a unit test fails when it is stale. Pattern from Arctic Fuse 3's `Includes_Fallbacks.xml` (ideas only, no code).
- **Why the fallback works.** `Includes.xml` loads the generated file early and the fallback last. Kodi keeps the first definition of an include, variable or expression name (`CGUIIncludes::LoadIncludes`, `LoadVariables` and `LoadExpressions` all use `try_emplace`, checked in xbmc master), and a missing include file is only logged at INFO (`Load_Internal`). So a fresh install or a clean clone uses the defaults, and a built install uses its own rows. Every name the generator writes is written whatever the row count (an empty `<definition>`, `[false]` expressions), so a build never mixes with the fallback's rows.
- **Only configured rows are bound.** `tools/build_home_row_bindings.py` and its 200 KB `Includes_Bald_HomeRows.xml` bound all 60 possible row ids (about 120 caption groups and 360 clearlogo images on Home). The generator now writes, per screen, only its configured rows: `Bald_ConfiguredArtLogos_<screen>` / `Bald_ConfiguredCaptions_<screen>` (combined by `Bald_ConfiguredArtLogos` / `Bald_ConfiguredCaptions`), `Bald_ItemOdd_<screen>`, `Bald_HasLogo_<screen>` and the two `Preview` forms (ORed by the old expression names in `Includes_Bald_Home.xml`), and the flat `Bald_Fanart` / `Bald_Logo` variables. The variables keep their exact old order: preview values for every row, then `$EXP[Bald_WidgetPreview]` giving empty (the old unconfigured preview branches returned an empty thumb, so a preview of a screen with no matching row stays blank), then the current-row values. They stay one flat variable, not per-screen variables nested with `$VAR`, because the dialog art depends on variables being evaluated with Home's window context and nesting was not checked live.
- **One "art row" property was considered and not done.** A single property for the row whose art shows would halve the variable branches, but it would have to be kept in step from every place that changes `Bald.Row`, `Bald.Row.<screen>`, `Bald.Menu` or `Bald.MenuPreview`, including the idle timer (500 ms granularity) and the dialog guards. With 3 to 8 rows the preview/current pairs now cost a handful of branches, so the expression pairs stay.
- **Generator syntax.** Checked against the installed Skin Variables 2.2.4 (`resources/lib/shortcuts/template.py`, `xmltojson.py`, jurialmunkey `parser.parse_math`): `$MATH[]` takes space-separated tokens evaluated left to right with no precedence; rule conditions `a==b` / `a!=b` are compared in Python, anything else goes to `xbmc.getCondVisibility`. Bald's generator uses only the Python comparisons, so `tools/build_home_defaults.py` can reproduce the build. Its output was compared byte for byte with the real `ShortcutsTemplate.create_xml` (Kodi modules stubbed) for the shipped defaults, and the real code also built cleanly from the live row lists in `userdata/addon_data/script.skinvariables/nodes/skin.bald/`.
- **Multi-line expressions.** Parts are joined with newlines. Kodi's `InfoExpression::Parse` skips whitespace only after an operator (Kodi turns off TinyXML whitespace condensing), so every generated expression line starts with `| [` and ends with `]`; a test checks this.
- **When it builds.** Home's `onload` runs `RunScript(script.skinvariables,action=buildtemplate,lastbuildtime=$INFO[Skin.String(Bald.WidgetsStamp)])`. Skin Variables' `update_xml` hashes its arguments, the generator config text and the current output file, compares with `Skin.String(script-skinvariables-generator-hash)` and returns when they match; otherwise it writes the file, stores the new hash and calls `ReloadSkin()`. So it builds on first run (no file, no hash), when the widget editor has closed since the last build (Custom_1116's `onunload` stamps `Bald.WidgetsStamp`), and after a skin update that changed the generator: `tools/build_home_defaults.py` writes a digest of `shortcuts/generator/` and the row defaults into the config's `buildv`, because the hash covers only the config text. The editor used to rebuild with `force` as it closed; the rebuild (and its skin reload) now happens on the next Home load, as in Arctic Fuse 3. The first Home load after this change rebuilds once, since the arguments changed.
- **Row start for every row.** The one-shot `bald_rowstart_*` timers covered only 9101 to 9103, 9201 and 9301; rows 9104+, 9202+ and 9302+ kept the fixedlist's pristine item 3. Timers.xml cannot be generated, so the timers stay for the rows that can show before they are focused, and two actions cover the rest: each generated row's `onfocus` moves the next row back while that row is hidden and already loaded (rows count as visible until their items load, docs "Hidden lists do not load"), and `Bald_Row`'s own `onfocus` corrects a row that is still pristine when focused (it slides while fading in; only happens when the viewer outruns loading). All paths share the `Bald.Start<id>` mark, which Home's `onload` clears for every configured row (`Bald_RowStartReset`). Kodi evaluates all of an action list's conditions before running any action and runs skin actions and skin timers on the GUI thread, so two paths cannot both move a row. A row is marked once focused with items, so later item 3 at slot 2 is left alone. Pre-existing caveat, now for every row: Home's `onload` clears the marks on every load, so a row the viewer left on item 3 at slot 2 before leaving Home (for example to play something) is moved back to item 1 when it is next focused, as the timers already did for the first three rows.
- **Row dots and the menu note.** Each generated row passes `dots` (the name of a generated `Bald_RowDots_<id>` include: one dot per row of its screen, the current one bright) and `dots_width` to `Bald_Row`, which includes `$PARAM[dots]` (a parameter as the include name, as Arctic Fuse 3 does). The Home menu note is `$VAR[Bald_RowsNote_home]`: a chain of generated variables, one per row, each holding its label and `, $VAR[...]` of the next, because the generator joins parts with newlines and Kodi would render those in a label. The head variable is written for every screen and is empty without rows.
- **No rows.** The widget editor hides Remove widget on a screen's last row, but a row list can still be emptied by hand. The generator writes `Bald_HasRows_<screen>` (`[false]`, plus `| [true]` per row). With no Home rows, Home's `onload` clears `Bald.Row` and focuses the menu's Home entry (which opens the menu) instead of leaving `defaultcontrol` 9101 pointing at nothing; menu Back only closes the menu while there is a current row; the idle wake button focuses `$VAR[Bald_RowFocus]` (the current row, else 9001), and ambient advance skips an empty `Bald.Row`. Entering a screen from the menu requires that screen to have rows.
- **Home menu navigation belongs to the grouplist.** Commit 390441c gave each menu button hand-written Up/Down chains for every combination of hidden Movies, TV shows and Live TV, setting `Bald.MenuPreview` and `TMDbHelper.WidgetContainer` before moving, because the menu was then a plain group. Since 6e08b0e made it a grouplist, those chains have not run: `CGUIControlGroupList::AddControl` replaces each child's Up and Down actions with its neighbours (`SetAction(..., replace=true)`; only Left, Right and Back are kept when set), and `CGUIWindow::OnMove` follows a hidden neighbour's own navigation to the next focusable one. So the preview has come from each button's `onfocus` alone, which runs as focus lands. The chains and their ~40 parameters are gone: `Bald_HomeMenuButton` takes id, label, preview, visible, suffix and right, and what Select does is passed as nested `<onclick>` children (`Bald_HomeMenuScreen` for Home, Movies and TV shows, which also retargets TMDb Helper in `onfocus`). One behavior change: with no `onup`/`ondown` of its own the grouplist wrapped the last entry to the first and back; 9000 now has `noop` for both, restoring the non-wrapping ends the old chains described.
- **Left runs Select.** Left used to repeat each entry's four actions; it is now `Action(Select)`, which Kodi sends to the focused control (the button, since a Left with no navigation keeps focus) and which runs the same `<onclick>` list. Not checked live.
- **Still to verify in Kodi:** Up and Down through the menu with Movies, TV shows and Live TV each hidden and shown (previews and backdrop follow, the ends do not wrap); Left on every entry does what Select does; Home with an empty Home row list opens on the menu and stays usable (Back, idle wake, Movies and TV shows entries); the row dots and the Home menu note with 1, 3 and 5 rows; rows 4 and later, and each screen's second row, open on their first item without a visible slide; the first Home load builds and reloads once, later loads do not; closing the widget editor and returning Home rebuilds once; a reload with both files present shows no include or expression errors in `kodi.log`; the per-screen `$EXP` combiners behave exactly as the old single expressions (parity crossfades, menu previews, dialog-over art).

## Milestone 3

- **Animation model (final).** Kodi animations are state-driven: Visible/Hidden fire on edges of a visibility condition and Conditional animations expect their condition to hold. Every item-change transition is therefore keyed to a state that flips on each move and then holds: the parity of the current row's item position (`Integer.IsOdd(Container(c).CurrentItem)`). Each animated piece exists twice (Odd and Even): the incoming instance becomes visible and plays its Visible animation; the outgoing one hides. Images keep their old texture while a Hidden animation plays (`CGUIImage::UpdateInfo`), so fanart and clearlogos fade out showing the old picture, a true crossfade; hidden images keep updating otherwise, so they are never stale when shown again. Labels cannot freeze, so caption text has no Hidden animation and disappears at once while the new text staggers in. Row swaps and the menu use Visible/Hidden on groups keyed to `Bald.Row` and `Bald.Menu`. Known gap: the ambient advance wrapping from the last to the first item of an odd-length row keeps the parity, so that one step swaps without animating.
- **What did not work, and why.** (1) `Container.OnNext` / `OnPrevious` as the condition of `reversible="false"` Conditional animations: true for one frame only, and `CAnimation::UpdateCondition` resets a non-reversible animation when its condition turns false, so animations started and were cancelled. (2) Skin timers recording the shown item: `CSkinInfo::ProcessTimers` runs from `CApplication::ProcessSlow`, every 500 ms, so updates lagged at random (judder). (3) Hiding on `OnNext` in `<visible>`: worked for text but led to layered fanart workarounds that ghosted. (4) `Container.Scrolling` in a hide condition: briefly true at the end of every scroll, which blinked the caption out after each scrolling move.
- **Comparing two infolabels.** `String.IsEqual(A,B)` compares two infolabels directly. `$INFO[...]` inside a condition fails to parse in `Timers.xml` ("Misplaced ["); it is fine inside actions. Do not quote `SetProperty` values (quotes are stored literally).
- **Skin timers are slow.** They run every 500 ms: fine for the row-start fix, idle and ambient, never for per-item behavior. A timer's stop condition must not depend on the thing it tracks, or it can get stuck running.
- **Fanart.** Two parity layers (`Bald_ArtLayer`): the incoming layer fades in (700, sine) while zooming 1.05 to 1.0 (1500); the outgoing layer fades out (700) with the old art. A row swap that keeps the parity changes the visible layer's texture, which `<fadetime>700</fadetime>` crossfades (Kodi 22 waits until the new image has loaded, then fades the old one out behind it).
- **Clearlogo preload.** Logos not yet in Kodi's texture cache could arrive after their fade-in ended and pop. A `<fadetime>` on the logo fixed that but crossfaded from the previous logo, so old logos ghosted under new ones. Instead each row tile draws an invisible (alpha 0) copy of its item's clearlogo, which loads it into the texture cache while the tile is on screen.
- **Do not use `Container.Scrolling` for hide conditions.** It is true while the scroll timer has run longer than the scroll duration, which includes a frame at the end of *every* 440 ms row scroll before the timer stops. Used in the caption's visibility it hid the caption for that frame, so every scrolling move faded the caption in, blinked it out about 450 ms later, and faded it in again (measured from a screen recording). Hold-while-fast-scrolling comes for free instead: each repeat of a held key hides the caption (`OnNext`) and restarts its delayed fade-in, so it stays hidden until the key is released.
- **Measuring motion.** Kodi's screenshot action is too slow and counts as input. Record the Kodi window with `screencapture -v -V 3 -x -R<x,y,w,h>` (Kodi must be frontmost and awake), extract frames with `ffmpeg -fps_mode passthrough`, and track mean brightness of screen regions per frame to find pops.
- **Art and caption follow the current row, not focus.** With the menu (or the idle wake button) focused, `ListItem.*` no longer points at a row, so the art frame and captions read `Container(9101..9103)` selected by the `Bald.Row` window property. Captions and clearlogos are one instance per row (includes with a container param).
- **Zoom clipping.** Neither a group nor a grouplist clips a zoom-animated texture, so the 1.05 settle zoom spilled outside the frame. Four field-colored mask bars around the frame hide the overflow. Revisit for milestone 4, where the frame zooms to full screen and the masks must get out of the way.
- **Hidden lists do not load.** Kodi skips `Process()` for hidden controls, so a hidden row's content was only fetched when first shown (and its start-item fix ran visibly late). Rows now count as visible until their items have loaded.
- **Window properties survive ReloadSkin.** Home's `onload` resets `Bald.Row`, `Bald.Menu` and the row-start flags every time.
- **Focus while hidden.** The menu list and rows use `<visible allowhiddenfocus="true">` so `SetFocus` works before the fade-in has made them visible.
- **Edge nudge.** Replayed by flipping a window property between `a` and `b` in one atomic `SetProperty` (via a variable), so each press retriggers a `reversible="false"` animation.
- **Menu hint counter.** `Skin.String(Bald.MenuOpens)` counts opens. The spec hides the "Back for menu" hint at 3; that is disabled for now (it kept looking like a bug during development) and returns in 0.2 as an Appearance setting. Reset it with JSON-RPC `Settings.SetSkinSettingValue` (`setting: "bald.menuopens"`, `value: ""`), since skin setting ids are lower-cased there.
- **Idle.** `bald_idle` (60 s) closes the menu and parks focus on an invisible button (9199) so the first key press only wakes. `bald_ambient` advances the current row every 8 s while idle (turn off with `Skin.SetBool(Bald.AmbientOff)`; the Appearance setting comes in 0.2). The drift is two `pulse` slides, 2 px on x (23 s) and y (31 s). Note: Kodi's screenshot action counts as input and ends idle.
- **Keyboard Back.** On a keyboard, Esc sends `PreviousMenu`, not `Back`, so it does nothing on Home. Backspace (and a remote's Back) opens and closes the menu.
- **Movies, TV shows, Live TV, Search** are menu placeholders with no rows yet; highlighting one previews a note in the row area, and Select or Left keeps you in the menu.
- **Caption title wraps upward.** The title is a `textbox` with `<height max="132">auto</height>` (up to 3 lines of 44 px) inside its own vertical grouplist with `<align>right</align>`, which bottom-aligns it (`CGUIControlGroupList::GetAlignOffset`). Its last line always ends at y 464 and the rest of the caption does not move. Past three lines it is cut off without an ellipsis.
- **Baselines.** Kodi labels align only top or center, so mixed-size labels on one line (section name and hint, row label and count) are top-aligned with the smaller one offset down by the size difference; Instrument Sans' ascender equals the font size.
- **Callout removed.** The dot and hairline between the art and the caption were trialled on and off in Kodi and removed (docs/SPEC.md section 5.1 updated).

## Background (pulled forward from section 7)

- **Tinted field, tried and replaced.** TMDb Helper's colors feature (mean color of a 128 px thumbnail, lightness and saturation forced by `Skin.String(TMDbHelper.Colors.Luminance)` / `...Saturation`) gave a field color, but at the spec's 7% lightness even 35 to 60% saturation reads as near-black (7% lightness caps the brightest channel at about 14%). Its own color stepping floors each step to an integer, so dark colors jumped; a two-layer crossfade fixed that. The user preferred a blurred fanart background instead, so the color tint was removed (see git history for the layers and timer).
- **Blurred fanart.** TMDb Helper's blur (`plugin.video.themoviedb.helper` 6.17.4, `lib/monitor/images.py`): the skin sets `Skin.SetBool(TMDbHelper.EnableBlur)` and `Window(Home).Property(TMDbHelper.Blur.SourceImage)` = `Art(fanart)|Art(tvshow.fanart)|Art(thumb)`, leaves `TMDbHelper.Service` off (no TMDB lookups), and names the watched row in `TMDbHelper.WidgetContainer` (set by each row on focus). It publishes `Window(Home).Property(TMDbHelper.ListItem.BlurImage)`: a 480 px copy with a Gaussian blur of radius 40 (`Skin.String(TMDbHelper.Blur.Size)` / `...Radius` change these), cached as JPEG under its addon_data. The background image darkens it with `colordiffuse` `bald_backdrop` (30%) and crossfades with `<fadetime>800</fadetime>`, which waits for the new image to load.
- **Menu preview backdrop.** Kodi's static list items do not provide a per-item focus action, so the main menu uses a grouplist of focusable buttons. Each button sets `Bald.MenuPreview`; Home, Movies and TV Shows also retarget TMDb Helper to that screen's remembered widget row. The foreground preview, clearlogo and cached Gaussian backdrop therefore share one explicit screen selection and remain synchronized without substituting sharp fanart while the menu is open.
- **Frame masks as windows.** The bars that hide the art frame's settle-zoom overflow are grouplists (which clip ordinary textures) containing the same full-screen background offset back to 0,0, so they line up with it exactly (`Bald_BackdropWindow`).
- **Accent and ink** stay neutral.
- **Letterboxing.** The skin defines only a 16:9 layout; fullscreen on a non-16:9 display (the MacBook's built-in screen is about 1.55:1) shows a black band.

- **Conditions have no window context (the real cause of the wrong info backdrop).** `CGUIControl::UpdateVisibility` and animation conditions evaluate with `INFO::DEFAULT_CONTEXT`; with no window given, `GetWindowWithCondition` falls back to the topmost modal dialog, so under the info dialog or the context menu any `Container(9101..9103)` inside a `<visible>` or animation condition resolves against the dialog and reads empty. Labels and textures are evaluated with the control's own window (`CGUIImage::UpdateInfo` passes `m_parentID`), and skin variables pass that context to their conditions (`CSkinVariableString::GetValue`). So Home's parity art layers flipped or blanked under dialogs, while a texture of `$VAR[Bald_Fanart]` stays right. Fix: while `Bald_DialogOver` (any modal dialog, info or context menu), the art frame shows a dialog-art image and a dialog logo/scrim whose textures are the live variables and whose visibility needs no container; they linger 900 ms after close while the layers settle. Rows guard their "still loading" visibility with `!Bald_DialogOver`. Two earlier attempts (a fanart snapshot property on Select, then also in `onunfocus`) were wrong: onunfocus does not fire when a dialog opens (focus is per window), and a stale snapshot showed the previous title.
- **More like this.** Library titles sharing the first genre, best rated first, excluding the current title, as a URL smart playlist. The initial English-prefix table was replaced in the review fixes below: the helper now reads the actual genre array and URL-encodes the JSON.
- **Masked images.** A `diffuse` mask stretches over the whole image, including what `aspectratio scale` crops away, so circles became clipped ovals on portrait photos. `<aspectratio scalediffuse="false">` keeps the mask fixed to the control.
- **Grouplist navigation.** A grouplist's `ondown`/`onup` do not apply to its children: the focused button's own navigation is used, so each action pill carries `ondown` (to Cast, or Details when there is no cast) and sets `Bald.InfoSec` in its own `onfocus`. The grouplist also remembers its last focused child, so `onload` focuses Resume or Play explicitly.
- **Driving Kodi for tests.** In JSON-RPC `Input.ButtonEvent` with keymap `KB`, Select is `enter` (not `return`).
- **Context menu as the Home menu.** `DialogContextMenu.xml` draws Kodi's context menu like the main menu (1440, 392; 46 px items). `CGUIDialogContextMenu` centres the dialog on the focused control using background image 999's size and clamps it to the screen, so 999 is an invisible image taller than the screen by the list's maximum height (1080 + 592). `SetupButtons` shrinks 999 by the list's unused height (its max minus its content), so a plain full-screen 999 ended up shorter than the screen and the dialog landed about 100 px low; at 1672 px it always stays screen-sized and the clamp lands the dialog at 0,0. Under the context menu the same no-context rule applies; the dialog art and dialog logo cover it.
- **Idle wake and C.** While idle, focus is parked on the wake button, which does not treat C (context menu) as a wake key, so the first C after idle does nothing.
