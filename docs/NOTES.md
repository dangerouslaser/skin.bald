# Build notes

Things from docs/SPEC.md that did not map directly onto Kodi 22, with what was tried and what was done instead.

## Episode detail and Search surfaces (2026-09-25)

- Episode info must key its presentation from `String.IsEqual(ListItem.DBType,episode)`: Kodi22's native episode dialog exposed all episode labels while `ListItem.IsEpisode` remained false in the verified library route. Overview now shows the episode title and parent-series/S-E metadata even when inherited series clearlogo art exists. Cast posters use center-crop `scale` in the fixed2:3 frame.
- Episode recommendations resolve `VideoLibrary.GetEpisodeDetails.tvshowid`, then use the parent show's title and first genre to build the existing safe TV-show smart-playlist. Invalid parents fail closed, and the identity guard rejects results from a replaced dialog after either lookup. Live verification returned TV-series recommendations, opened series details, and safely returned to the originating episode library selection.
- Home Search now opens chooser1107, using the shared right-menu geometry and native Global Search/Add-ons/YouTube destinations. Global Search was not installed during QA, so Kodi's install prompt was declined; no add-ons were installed.
- The alphabet keyboard keeps Kodi's native controls/navigation but uses Bald surfaces and focus colors. Character keys use bundled Kodi22 Estuary `NotoSans-Regular.ttf` (with its license) because Instrument Sans lacks several Kodi-generated symbol-layer glyphs (`±`, `μ`, `¤`). Styling is scoped to `DialogKeyboard`; `DialogNumeric` retains its existing shared style. Live QA covered letters, accents/symbols, shift/caps, cursor/backspace/space, autocomplete, confirm/cancel and Home return. Numeric/password variants remain outstanding because no non-mutating route was available.

## Milestone 1

- **Clock weight 300.** Instrument Sans ships static TTFs from 400 (Regular) to 700 (Bold); there is no Light. `Bald_Clock` uses Regular for now. Options later: generate a 300 instance from the variable font with fontTools (`varLib.instancer`; the wght axis starts at 400, so this needs a different face or accepting 400).
- **Letter spacing.** Kodi's Font.xml has no tracking or letter-spacing property, so the spec's -0.045em, -0.02em, -0.03em and +0.04em values are not applied.
- **Line height.** `<linespacing>` multiplies the font's own line height, not the point size. Caption plot (1.5) and info plot (1.55) are first guesses at 30 px and 34 px lines; measure and tune in milestone 2.
- **Variable fonts.** Kodi's FreeType path renders only the default instance of a variable TTF, so the repo ships the static Regular, Medium, SemiBold and Bold files from github.com/Instrument/instrument-sans.
- **Estuary font names.** The Default fontset keeps every Estuary font name and size so the copied utility windows render; `<style>bold</style>` entries now use the SemiBold file, and the synthetic `lighten` and `bold` styles are dropped. The Arial fontset (for non-Latin languages) is unchanged apart from the added Bald_* names.
- **Switching skins remotely.** Setting `lookandfeel.skin` over JSON-RPC loads the skin, but Kodi's "keep this skin?" confirmation closes immediately and reverts. Workaround: quit Kodi, set `lookandfeel.skin` to `skin.bald` in `userdata/guisettings.xml`, and relaunch. `kodi-send` is not installed on this Mac; the event server is enabled if it is added later.
- **Resolution folder.** One `<res>` entry, 1920 x 1080, folder `1080i`, as the spec says. Estuary's extra aspect-ratio entries were dropped.

## Milestone 2

- **Plot ellipsis.** Kodi cannot end a multi-line block with "...". `CGUITextLayout::WrapText` draws `ceil(height / line height)` lines and stops; a `textbox` clips. Only single-line labels truncate with an ellipsis (by width). The caption plot is a `wrapmultiline` label 116 px tall with 30 px lines, so it stops cleanly at 4 lines. A real ellipsis would need a service to pre-trim the text into a window property; revisit alongside the palette service (section 7).
- **Line spacing measured.** Instrument Sans' natural line is about 1.2 x size. Caption plot uses 1.25 (20 px -> 30 px lines), info plot 1.29 (22 px -> 34 px).
- **Fixedlist focus.** Kodi's `movement` lets the cursor travel *below* `focusposition`, not above it. `focusposition 2, movement 2` gives the prototype's behavior: focus travels right to slot 2, then the row scrolls, and it stays at slot 2 going back left. A freshly loaded fixedlist starts with its cursor at `focusposition` (item 3), and `SetFocus(id,0,absolute)` in `onload` runs before the content exists. Fixed in milestone 3 with one-shot skin timers (`bald_rowstart_*` in `Timers.xml`) that wait for a row to finish loading and, if it is in that pristine state (item 3 at position 2), move it back two items.
- **Row sources.** Kodi library only. Continue watching is two skin playlists (`inprogress_movies.xsp`, `inprogress_episodes.xsp`) as two `<content>` elements in one list; Kodi concatenates them, so movies come first rather than interleaving by last played. Next up is `videodb://inprogresstvshows/` (shows, not the next episode). Rows become user-configurable widgets in 0.2.
- **Clearlogo drop shadow.** Not implemented; Kodi images have no blur or shadow. Options later: a pre-blurred shadow texture behind the logo, or leave it (logo scrim already provides contrast).
- **Genres.** `ListItem.Genre` joins with " / " (Kodi's separator), not the prototype's ", ".
- **Dev window.** The macOS Kodi window must be 16:9 or the GUI is stretched. Set to 1600 x 900 content (1600 x 928 with title bar) via System Events.

## Milestone 3

- **Animation model (final).** Kodi animations are state-driven: Visible/Hidden fire on edges of a visibility condition and Conditional animations expect their condition to hold. Every item-change transition is therefore keyed to a state that flips on each move and then holds: the parity of the current row's item position (`Integer.IsOdd(Container(c).CurrentItem)`). Each animated piece exists twice (Odd and Even): the incoming instance becomes visible and plays its Visible animation; the outgoing one hides. Images keep their old texture while a Hidden animation plays (`CGUIImage::UpdateInfo`), so fanart and clearlogos fade out showing the old picture, a true crossfade; hidden images keep updating otherwise, so they are never stale when shown again. Labels cannot freeze, so caption text has no Hidden animation and disappears at once while the new text staggers in. Row swaps and the menu use Visible/Hidden on groups keyed to `Bald.Row` and `Bald.Menu`. Known gap: the ambient advance wrapping from the last to the first item of an odd-length row keeps the parity, so that one step swaps without animating.
- **What did not work, and why.** (1) `Container.OnNext` / `OnPrevious` as the condition of `reversible="false"` Conditional animations: true for one frame only, and `CAnimation::UpdateCondition` resets a non-reversible animation when its condition turns false, so animations started and were cancelled. (2) Skin timers recording the shown item: `CSkinInfo::ProcessTimers` runs from `CApplication::ProcessSlow`, every 500 ms, so updates lagged at random (judder). (3) Hiding on `OnNext` in `<visible>`: worked for text but led to layered fanart workarounds that ghosted. (4) `Container.Scrolling` in a hide condition: briefly true at the end of every scroll, which blinked the caption out after each scrolling move.
- **Comparing two infolabels.** `String.IsEqual(A,B)` compares two infolabels directly. `$INFO[...]` inside a condition fails to parse in `Timers.xml` ("Misplaced ["); it is fine inside actions. Do not quote `SetProperty` values (quotes are stored literally).
- **Skin timers are slow.** They run every 500 ms: fine for the row-start fix, idle and ambient, never for per-item behavior. A timer's stop condition must not depend on the thing it tracks, or it can get stuck running.
- **Fanart.** Two parity layers (`Bald_ArtLayer`): the incoming layer fades in (700, sine) while zooming 1.05 to 1.0 (1500); the outgoing layer fades out (700) with the old art. A row swap that keeps the parity changes the visible layer's texture, which `<fadetime>700</fadetime>` crossfades (Kodi 22 waits until the new image has loaded, then fades the old one out behind it).
- **Clearlogo preload.** Logos not yet in Kodi's texture cache could arrive after their fade-in ended and pop. A `<fadetime>` on the logo fixed that but crossfaded from the previous logo, so old logos ghosted under new ones. Instead each row tile draws an invisible (alpha 0) copy of its item's clearlogo, which loads it into the texture cache while the tile is on screen.
- **Do not use `Container.Scrolling` for hide conditions.** It is true while the scroll timer has run longer than the scroll duration, which includes a frame at the end of *every* 440 ms row scroll before the timer stops. Used in the caption's visibility it hid the caption for that frame, so every scrolling move faded the caption in, blinked it out about 450 ms later, and faded it in again (measured from a screen recording). Hold-while-fast-scrolling comes for free instead: each repeat of a held key hides the caption (`OnNext`) and restarts its delayed fade-in, so it stays hidden until the key is released.
- **Measuring motion.** Kodi's screenshot action is too slow and counts as input. Record the Kodi window with `screencapture -v -V 3 -x -R<x,y,w,h>` (Kodi must be frontmost and awake), extract frames with `ffmpeg -fps_mode passthrough`, and track mean brightness of screen regions per frame to find pops.
- **Art and caption follow the current row, not focus.** With the menu (or the idle wake button) focused, `ListItem.*` no longer points at a row, so the art frame and captions read `Container(9101..9103)` selected by the `Bald.Row` window property. Captions and clearlogos are one instance per row (includes with a container param).
- **Zoom clipping.** Neither a group nor a grouplist clips a zoom-animated texture, so the 1.05 settle zoom spilled outside the frame. Four field-colored mask bars around the frame hide the overflow. Revisit for milestone 4, where the frame zooms to full screen and the masks must get out of the way.
- **Hidden lists do not load.** Kodi skips `Process()` for hidden controls, so a hidden row's content was only fetched when first shown (and its start-item fix ran visibly late). Rows now count as visible until their items have loaded.
- **Window properties survive ReloadSkin.** Home's `onload` resets `Bald.Row`, `Bald.Menu` and the row-start flags every time.
- **Focus while hidden.** The menu list and rows use `<visible allowhiddenfocus="true">` so `SetFocus` works before the fade-in has made them visible.
- **Edge nudge.** Replayed by flipping a window property between `a` and `b` in one atomic `SetProperty` (via a variable), so each press retriggers a `reversible="false"` animation.
- **Menu hint counter.** `Skin.String(Bald.MenuOpens)` counts opens. The spec hides the "Back for menu" hint at 3; that is disabled for now (it kept looking like a bug during development) and returns in 0.2 as an Appearance setting. Reset it with JSON-RPC `Settings.SetSkinSettingValue` (`setting: "bald.menuopens"`, `value: ""`), since skin setting ids are lower-cased there.
- **Idle.** `bald_idle` (60 s) closes the menu and parks focus on an invisible button (9199) so the first key press only wakes. `bald_ambient` advances the current row every 8 s while idle (turn off with `Skin.SetBool(Bald.AmbientOff)`; the Appearance setting comes in 0.2). The drift is two `pulse` slides, 2 px on x (23 s) and y (31 s). Note: Kodi's screenshot action counts as input and ends idle.
- **Keyboard Back.** On a keyboard, Esc sends `PreviousMenu`, not `Back`, so it does nothing on Home. Backspace (and a remote's Back) opens and closes the menu.
- **Movies, TV shows, Live TV, Search** are menu placeholders with no rows yet; highlighting one previews a note in the row area, and Select or Left keeps you in the menu.
- **Caption title wraps upward.** The title is a `textbox` with `<height max="132">auto</height>` (up to 3 lines of 44 px) inside its own vertical grouplist with `<align>right</align>`, which bottom-aligns it (`CGUIControlGroupList::GetAlignOffset`). Its last line always ends at y 464 and the rest of the caption does not move. Past three lines it is cut off without an ellipsis.
- **Baselines.** Kodi labels align only top or center, so mixed-size labels on one line (section name and hint, row label and count) are top-aligned with the smaller one offset down by the size difference; Instrument Sans' ascender equals the font size.
- **Callout removed.** The dot and hairline between the art and the caption were trialled on and off in Kodi and removed (docs/SPEC.md section 5.1 updated).

## Background (pulled forward from section 7)

- **Tinted field, tried and replaced.** TMDb Helper's colors feature (mean color of a 128 px thumbnail, lightness and saturation forced by `Skin.String(TMDbHelper.Colors.Luminance)` / `...Saturation`) gave a field color, but at the spec's 7% lightness even 35 to 60% saturation reads as near-black (7% lightness caps the brightest channel at about 14%). Its own color stepping floors each step to an integer, so dark colors jumped; a two-layer crossfade fixed that. The user preferred a blurred fanart background instead, so the color tint was removed (see git history for the layers and timer).
- **Blurred fanart.** TMDb Helper's blur (`plugin.video.themoviedb.helper` 6.17.4, `lib/monitor/images.py`): the skin sets `Skin.SetBool(TMDbHelper.EnableBlur)` and `Window(Home).Property(TMDbHelper.Blur.SourceImage)` = `Art(fanart)|Art(tvshow.fanart)|Art(thumb)`, leaves `TMDbHelper.Service` off (no TMDB lookups), and names the watched row in `TMDbHelper.WidgetContainer` (set by each row on focus). It publishes `Window(Home).Property(TMDbHelper.ListItem.BlurImage)`: a 480 px copy with a Gaussian blur of radius 40 (`Skin.String(TMDbHelper.Blur.Size)` / `...Radius` change these), cached as JPEG under its addon_data. The background image darkens it with `colordiffuse` `bald_backdrop` (30%) and crossfades with `<fadetime>800</fadetime>`, which waits for the new image to load.
- **Frame masks as windows.** The bars that hide the art frame's settle-zoom overflow are grouplists (which clip ordinary textures) containing the same full-screen background offset back to 0,0, so they line up with it exactly (`Bald_BackdropWindow`).
- **Accent and ink** stay neutral.
- **Letterboxing.** The skin defines only a 16:9 layout; fullscreen on a non-16:9 display (the MacBook's built-in screen is about 1.55:1) shows a black band.

## Milestone 4 (movie info)

- **Reference.** `~/Downloads/bald-reference-prototype.html` (home, movie info, TV info, customize) gives the info spacing, stagger, section opacities, pill buttons, cast and tile styles, and the handoff timings. Its header calls it the behavioral source of truth alongside the spec.
- **Contract controls.** `CGUIDialogVideoInfo` plays with id 8 and resumes with id 9; when a resume control exists, 8 always plays from the beginning. 11 plays the trailer, 50 is the cast list Kodi fills. They are hidden buttons; the visible pills `SendClick` them.
- **Mark watched: not implemented.** Kodi has no builtin a skin can call to toggle watched state, the video info dialog ignores ToggleWatched, and neither TMDb Helper nor script.skinvariables offers one. Open item.
- **Handoff lives in Home.** Info is a dialog over Home. Paired non-reversible Conditionals on `Window.IsVisible(movieinformation)` zoom the art frame to full screen (1.53846 about 274,343; 640 after 40, back 540) and move Home's chrome out and back; Kodi applies a Conditional's end state silently at window load.
- **Conditions have no window context (the real cause of the wrong info backdrop).** `CGUIControl::UpdateVisibility` and animation conditions evaluate with `INFO::DEFAULT_CONTEXT`; with no window given, `GetWindowWithCondition` falls back to the topmost modal dialog, so under the info dialog or the context menu any `Container(9101..9103)` inside a `<visible>` or animation condition resolves against the dialog and reads empty. Labels and textures are evaluated with the control's own window (`CGUIImage::UpdateInfo` passes `m_parentID`), and skin variables pass that context to their conditions (`CSkinVariableString::GetValue`). So Home's parity art layers flipped or blanked under dialogs, while a texture of `$VAR[Bald_Fanart]` stays right. Fix: while `Bald_DialogOver` (any modal dialog, info or context menu), the art frame shows a dialog-art image and a dialog logo/scrim whose textures are the live variables and whose visibility needs no container; they linger 900 ms after close while the layers settle. Rows guard their "still loading" visibility with `!Bald_DialogOver`. Two earlier attempts (a fanart snapshot property on Select, then also in `onunfocus`) were wrong: onunfocus does not fire when a dialog opens (focus is per window), and a stale snapshot showed the previous title.
- **More like this.** Library titles sharing the first genre, best rated first, excluding the current title, as a URL smart playlist. The initial English-prefix table was replaced in the review fixes below: the helper now reads the actual genre array and URL-encodes the JSON.
- **Masked images.** A `diffuse` mask stretches over the whole image, including what `aspectratio scale` crops away, so circles became clipped ovals on portrait photos. `<aspectratio scalediffuse="false">` keeps the mask fixed to the control.
- **Grouplist navigation.** A grouplist's `ondown`/`onup` do not apply to its children: the focused button's own navigation is used, so each action pill carries `ondown` (to Cast, or Details when there is no cast) and sets `Bald.InfoSec` in its own `onfocus`. The grouplist also remembers its last focused child, so `onload` focuses Resume or Play explicitly.
- **Driving Kodi for tests.** In JSON-RPC `Input.ButtonEvent` with keymap `KB`, Select is `enter` (not `return`).
- **Context menu as the Home menu.** `DialogContextMenu.xml` draws Kodi's context menu like the main menu (1440, 392; 46 px items). `CGUIDialogContextMenu` centres the dialog on the focused control using background image 999's size and clamps it to the screen, so 999 is an invisible image taller than the screen by the list's maximum height (1080 + 592). `SetupButtons` shrinks 999 by the list's unused height (its max minus its content), so a plain full-screen 999 ended up shorter than the screen and the dialog landed about 100 px low; at 1672 px it always stays screen-sized and the clamp lands the dialog at 0,0. The focused item carries the Home menu's accent dot (a 440 x 56 focus texture with the dot at its left edge); the list starts 10 px left of the column because grouplists clip. Home reacts through `Bald_OverlayOpen` (main menu or context menu). This also gives **Mark as watched** from Kodi's own context items. Under the context menu the same no-context rule applies; the dialog art and dialog logo cover it.
- **Idle wake and C.** While idle, focus is parked on the wake button, which does not treat C (context menu) as a wake key, so the first C after idle does nothing.

## Alpha review fixes (2026-09-25)

- **Related-title replacement.** `Action(Info)` inside `CGUIDialogVideoInfo` closes the dialog. `RunScript(skin.bald,open,<type>,<dbid>)` instead fetches the local library item, builds a typed ListItem, closes the current dialog, waits for its close animation, then opens `xbmcgui.Dialog().info(item)`. It carries artwork, cast, resume and stream details into the native dialog. `Bald.InfoSwitch` holds Home's zoom during the exchange, suppresses repeat Select, and is released on the new dialog's onload (or on failure). Back returns to the originating tile, not a nested chain of dialogs. The script is a declared extension of this add-on with an `xbmc.python` dependency; invoking a bare script path generated a missing-dependency warning.
- **Safe recommendations.** The bundled helper uses local JSON-RPC to read `genre` as an array, takes the first entry without language assumptions, serializes JSON, and percent-encodes the entire `xsp` value. It never writes library data or runs a background service. `Bald.Identity` rejects late results from a previous dialog item. Missing genre or unsupported media produces no recommendations. Kodi can retain a provider's old items when a dynamic URL becomes empty, so the list and its focus routes also require a nonempty `Bald.MorePath`. `browse="never"` removes Kodi's extra Browse item from the 12-title recommendation row.
- **Artwork ownership.** Home still owns the specified frame zoom. The helper publishes the current info fanart directly as `Bald.Fanart` (no path interpolation into builtins); `Bald.ArtIdentity` prevents old dialog art from appearing before a new item's art is published. This overlay crossfades related art inside the zoomed frame and fades out over 130 FADE on final close, revealing the original tile again. Outside Home, the info dialog supplies a full-screen image with an opaque field behind it. An attempted bridge through a hidden native XML label was discarded: Python's `ControlLabel.getLabel()` does not read that native label's rendered text, and chaining it off a temporary Window wrapper crashed this Kodi build. The implementation uses only window properties, not native control wrappers.
- **Empty-data focus.** Details is now a focusable heading (5050) at the existing location. Actions fall back to it if Cast is empty; Cast falls back to it if recommendations are empty. Down stays put when nothing follows; Up returns to Cast or actions. Section 1 makes Details readable even with both lists empty.
- **Maintenance access.** Home's last alpha menu item opens native Settings, providing File manager, Media/library settings and Interface/skin selection without redesigning the Estuary utility windows. It scrolls into view within the existing menu viewport. Customize home remains deferred to 0.2.
- **Optional blur dependency.** `plugin.video.themoviedb.helper` 6.17.4 is declared optional. Home enables blur only when it is present; the blurred image also checks presence and a nonempty output property. Without it, Home and its frame masks use the existing `bald_field` base. Installing the optional helper enables the enhancement; core navigation and info do not depend on it.
